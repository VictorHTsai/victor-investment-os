Dynamic Game Engine

動態博弈市場狀態推演框架
Victor Investment OSDGE V1.1Primary Asset: BTCFalsifiable Walk-Forward

核心不是猜下一根 K 線，而是：識別狀態 → 推演參與者約束 → 建立條件路徑 → 用新證據持續更新。

重要原則：系統不聲稱知道任何單一「莊家」的私人庫存或意圖；它只判斷目前公開觀測最符合哪個 latent market state，並要求每個假說都有 next expected observation 與 invalidator。

1. 從價格預測轉向狀態推演

Observations → Regime → Hidden-State Hypothesis ↓ Scenario Tree → Test → New Evidence → Update ↑___________________________________|

DGE 把市場敘事轉成可被新資料支持或推翻的假說，而不是把一個故事固定成結論。

Sₜ = f(Rₜ, Lₜ, Fₜ, Cₜ, Pₜ, Vₜ, Dₜ, Eₜ, Tₜ)

4. 六狀態 Behavioral FSM

A

Accumulation

供給吸收或建倉證據增加。

T

Market Test

壓力正在測試價格與流量反應。

S

Shakeout

弱手或槓桿退出；觀察 marginal selling response 是否下降。

M

Markup

向上價格擴張與資金確認增強。

D

Distribution

供給壓力提高，新增資金推動價格的效率下降。

N

Neutral / Unclear

證據衝突、不足或正在轉換。

Σ P(Zₜ = z) = 1
輸出的是六種狀態的相對支持，而不是 BTC 上漲/下跌機率。

5. Test：最值得量化的核心

TestResponseₜ = ΔOrderFlowₜ / (|ΔPriceₜ| + ε)

比較相似價格衝擊究竟引出多少新增現貨供給；若連續 downside shock 的 marginal selling response 下降，才形成可檢驗的供給衰竭證據。

6. Scenario Tree

DGE 不預測單一路徑。每個主要情境都應包含 probability、path、trigger、invalidator、horizon。市場出現新證據後更新權重，而不是重寫舊故事。

7. Walk-Forward Audit

重要 snapshot 凍結後，以 7 / 14 / 30D future return、MFE、MAE、Brier calibration 與 baseline 比較。若 DGE 無法在 out-of-sample 提供增量價值，就應修改或刪除無效部分。

8. 核心紀律

  1. 不把「莊家」當成單一全知主體。
  2. 不輸出無資料支持的精確控盤率。
  3. 每個假說都有 horizon、next observation、invalidator。
  4. 新證據改概率，但不刪除舊預測。
  5. 技術指標是 evidence，不是答案。
  6. 只有 out-of-sample 仍有增量價值的參數才進正式系統。
Observe → Hypothesize → Test → Update → Falsify / Retain.
